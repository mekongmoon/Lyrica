# v2 Lean API

The v1 endpoint `/lyrics/` keeps its response format. `/v2` adds a compact
schema, ETag/304 support, explicit sync tiers, and small error envelopes. Both
are served by the same deployment and share one lyrics cache; there is no
separate v1 host or port.

!!! note "Stability"
    The `/v2/lyrics` response contract below is **frozen for `v2.0.0`**
    (see [#14](https://github.com/mekongmoon/Lyrica/issues/14)). After
    `v2.0.0`, fields may be *added*, but renaming, removing or changing the
    type or nesting of anything documented here requires a new major API
    version (`/v3`). Contract tests in `Test/test_v2_core.py` enforce this.

## `GET /v2/lyrics`

| Parameter | Default | Description |
|---|---|---|
| `artist` | required | Artist name |
| `song` | required | Song title |
| `tier` | `line` | `plain`, `line`, `word`, or `syllable` |
| `allow_lower` | `true` | Serve the best available lower tier when the requested tier is missing |
| `lite` | `false` | Omit `src`, `artist`, `title` and `dur` |
| `fields` | — | Comma-separated top-level fields to keep (`v` and `tier` are always kept) |
| `translate` | `false` | Translate with the instance's Groq key |
| `romanize` | `false` | Romanize/transliterate |
| `lang` | `en` | Target language for `translate` / `romanize` |
| `fast` | `false` | Query providers in parallel and return the first valid match |

### Response fields

| Field | Type | Present | Meaning |
|---|---|---|---|
| `v` | integer | always | API version, `2` |
| `tier` | string | always | Tier actually returned: `plain`, `line`, `word` or `syllable`. May be lower than requested when `allow_lower=true` |
| `src` | string | when known, unless `lite` | Provider that supplied the lyrics, e.g. `lrclib`, `lrcmux` |
| `artist` | string | when known, unless `lite` | Artist as reported by the provider |
| `title` | string | when known, unless `lite` | Song title as reported by the provider |
| `dur` | integer (ms) | when known, unless `lite` | Song duration in milliseconds |
| `lines` | array | `tier` is `line`, `word` or `syllable` | Timed lines (see below) |
| `text` | string | `tier` is `plain` | Plain lyrics, lines separated by `\n` |
| `tr` | array of strings | `translate=true` | Translated lines, one per entry in `lines` (or per line of `text`) |
| `rom` | array of strings | `romanize=true` | Romanized lines, aligned the same way |

Optional fields are **omitted** when unknown; they are never sent as `null`.
All times are integer **milliseconds** from the start of the song.

### `lines` nesting by tier

| Tier | One entry of `lines` |
|---|---|
| `line` | `[start, text]` |
| `word` | `[start, text, [[word_start, word], ...]]` |
| `syllable` | `[start, text, [[word_start, word, [[syllable_start, syllable], ...]], ...]]` |

There is no per-line `id` and no end time: a line ends where the next one
starts. At `word` and `syllable` tier, the word list of a line can be empty
(`[start, text, []]`) when the provider had no word timing for that line.

### Examples

```bash
curl "http://127.0.0.1:9999/v2/lyrics?artist=Coldplay&song=Yellow&tier=line"
```

```json
{
  "v": 2,
  "src": "lrclib",
  "tier": "line",
  "artist": "Coldplay",
  "title": "Yellow",
  "dur": 267000,
  "lines": [[35660, "Look at the stars"], [38460, "Look how they shine for you"]]
}
```

Word tier:

```json
{"v": 2, "tier": "word", "lines": [[35660, "Look at the stars", [[35660, "Look"], [37200, "at"], [37700, "the"], [38000, "stars"]]]]}
```

Syllable tier:

```json
{"v": 2, "tier": "syllable", "lines": [[35660, "Look", [[35660, "Look", [[35660, "Lo"], [35800, "ok"]]]]]]}
```

Plain tier:

```json
{"v": 2, "src": "lrclib", "tier": "plain", "artist": "Coldplay", "title": "Yellow", "dur": 267000, "text": "Look at the stars\nLook how they shine for you"}
```

`lite=true`:

```json
{"v": 2, "tier": "line", "lines": [[35660, "Look at the stars"]]}
```

### When the requested tier is unavailable

Word and syllable timing comes from **Lrcmux** and **Apple Music**, which are
tried first. If neither has the requested tier:

- `allow_lower=true` (default) returns the best lower tier available from
  **any** source, for example line-level lyrics from LRCLIB. The `tier` field
  says what you got.
- `allow_lower=false` returns `404 {"err": "tier_unavailable", "tier": "<best available>"}`.

A failed upgrade is remembered for a while, so repeated requests for a tier
that does not exist do not call providers again. (Whether word requests should
instead be limited to Lrcmux and Apple Music is open in
[#40](https://github.com/mekongmoon/Lyrica/issues/40); either way the response
format above is unchanged.)

### Errors

Errors are small JSON objects with an `err` code, plus at most one extra field:

| Status | Body | When |
|---|---|---|
| `400` | `{"err": "missing_artist_or_song"}` | `artist` or `song` missing |
| `400` | `{"err": "bad_tier", "allowed": ["plain", "line", "word", "syllable"]}` | Unknown `tier` |
| `404` | `{"err": "not_found"}` | No provider has the song |
| `404` | `{"err": "tier_unavailable", "tier": "<best available>"}` | `allow_lower=false` and the tier is missing |
| `500` | `{"err": "internal"}` | Unexpected server error |
| `502` | `{"err": "ai_failed"}` | Translation/romanization failed |
| `503` | `{"err": "upstream_unavailable"}` | Providers errored (not a clean miss); retry later |
| `503` | `{"err": "ai_unavailable"}` | `translate`/`romanize` requested but no Groq key is configured |
| `504` | `{"err": "timeout"}` | Fetching took too long |

Rate limiting (`429`) uses the server-wide error format described in the
[API overview](overview.md).

### Headers and caching

Every successful response carries:

- `ETag`: a strong validator, `"` + 32 hex characters + `"`. Send it back as
  `If-None-Match` to get `304 Not Modified` with an empty body.
- `X-Cache`: `HIT` when served from the response cache, `MISS` when rendered.

`Content-Type` is `application/json`.

## `GET /v2/capabilities`

Reports the supported tiers, the providers enabled on this instance, AI
availability, and whether responses are compressed (currently always `true`;
see [#17](https://github.com/mekongmoon/Lyrica/issues/17)).

```json
{"v": 2, "tiers": ["plain", "line", "word", "syllable"], "providers": ["genius", "lrclib", "lrcmux", "megalobiz", "netease", "youtube"], "ai": false, "byok": false, "compression": true}
```

## `GET /v2/health`

Reports per-provider breaker state, quota tokens, success/error/not-found
counters, p50/p95 latency, singleflight stats, negative-cache stats, and cache
stats. Provider failures are logged at `WARNING` with the provider name and
reason.

This endpoint is currently public. Whether to trim it or require the admin key
is open in [#15](https://github.com/mekongmoon/Lyrica/issues/15). Use `/health`
for liveness checks. `/v2/capabilities` and `/v2/health` are informational and
not part of the frozen `/v2/lyrics` contract.

## Provider safety

Every provider call passes through one choke point (`src/core/providers.py`):

- Token bucket per provider, seeded from `.lyrica.config` RPM values and
  overridable with `LYRICA_PROVIDER_<NAME>_RPM`.
- Circuit breaker: opens after 5 consecutive transport failures, cools down
  for 30 seconds, then allows a single probe and requires two good probes
  before closing.
- Per-loop bulkhead (`LYRICA_PROVIDER_CONCURRENCY`, default 8).
- Metrics: latency, success, errors, not-found, rejected.

A provider can be disabled with `LYRICA_DISABLED_PROVIDERS=genius,apple_music`.
